# 你只需要出刀2（KCRR 环奈连结R Relink）

### 补偿秒数与满补识别

监控记录确认击杀前的 Boss 剩余血量、原始伤害及战斗耗时，按
`min(90, ceil(110 - 战斗耗时 × 剩余血量 / 原始伤害))` 计算补偿秒数。
算法参考 [pcr_calculator_plus](https://github.com/watermellye/pcr_calculator_plus/blob/master/pcr_calculator.py)；
非合刀击杀等价于剩余时间加 20 秒，最多 90 秒。击杀播报追加“获得了xxs的返还时间”；补偿刀击杀不会再获得补偿。
无法可靠确认击杀前血量时不猜测秒数，迟到的战报或击杀证据会补充已保存记录。

同一玩家以 UTC+8 每天 05:00 划分游戏日，综合已获得补偿、后续起始时长、最多 3 次正常起刀重算类型。
尾刀也占一次正常起刀；接口的角色归属字段不能可靠排除支援，因此不因单个角色重复而否定完整刀。
同一玩家当天完整五人阵容完全相同（忽略站位顺序）时，不再作为新的正常起刀候选；若能唯一匹配已获得的90s补偿，即自动记为补偿。阵容不完整或换了全新阵容时仍保留必要的歧义；
与未消费尾刀阵容重复两个及以上角色时，同样排除正常起刀候选；仅重复一个角色可能来自支援，不用于强制判定。仍须有匹配的补偿可消费，多个解释不一致时保留待确认，人工修正优先。
若存在多种合法解释或历史不完整，保留原判定，不直接把超过 3 刀后的最后一刀改成补偿。管理员的手动修正优先。
新补充的记录会再次核对当天类型；旧数据缺少自有角色或原始血量时，无法保证还原全部满补。
启动本群监控时会重新核对当天已保存战报，不重发过去的击杀播报。
对缺少击杀前血量的记录，监控会按需完整抓取本期游戏战报，并核对分页前后的第一页未变化、
前周目同Boss击杀锚点可见、本周目战报全部唯一入库、末尾唯一确认击杀，以及配置满血与游戏当前满血一致。
满足条件后以满血减去前序有效伤害恢复血量、扣除溢出并重算返秒；每群最多每两分钟尝试一次。
分页失败、战报变化、缺少锚点/记录、重复或同秒顺序不明、跨阶段满血无法验证时跳过，不直接根据本地伤害之和猜测。
补抓不假定游戏分页的新旧顺序，逐页扫描并与数据库实际记录键核对，按时间从旧到新入库。
单条详情或某页失败会记录错误，其余记录继续处理，后续扫描会重试未入库记录，避免因最新时间游标跨过失败记录而永久漏记。
已唯一确定消费关系的补偿，可以用其实际起始秒数补全对应尾刀的秒数；
已知补偿与后续短秒数不匹配时报告冲突，不再把旧补偿错误地显示为确定剩余。

群内发送 `剩余补偿`（或 `查补偿`）查看全群今日未用补偿，发送 `我的补偿` 查看绑定账号；
可 @ 成员查询其账号，沿用已有账号查询权限。示例：`子非鱼：90s×1、26s×1`。
查询会扣除已使用的补偿，按 05:00 换日，只根据本群今日已记录战报推算。
若不能唯一判断某刀是否已消耗补偿，显示 `待确认：90s×0～1`；缺少击杀前血量时显示秒数未知，
记录冲突时显示无法确认，不把这些情况直接当作可用补偿。

### 群指令「分数线」图片

个人会战操作支持代操作：`sl @成员`、`sl? @成员`、`不打了 @成员`、`进3 @成员`、
`预约 2 @成员`、`取消预约 2 @成员`、`挂树 3 @成员`、`下树 @成员` 等，均操作被 @ 成员的记录，
不 @ 时操作本人。@ 可放在指令前或后，留言不包含 @ 代码；清空全体记录的指令仍要求管理员权限。
状态图片的预约、申请和挂树名单同样显示成员 QQ 头像，加载失败时显示名字首字。

`分数线` 复用 WebUI 档线表和现有档线缓存，返回档位、合计分数、守线公会、会长及人数。
没有公会的占位档位不显示，不包含右侧档位奖励和我会差距，保留本公会与前三名、末位高亮。
需开启出刀监控并部署新版 WebUI；截图配置与「状态」「今日出刀」共用。

### 首日满补模式

针对首日 B/C 阶段留下的 90 秒补偿在 D 阶段被误判为完整刀，提供按群独立的开关，默认关闭。
群主、管理员或 bot 主人发送 `开启首日满补`（或 `开启首日满补 自动`），即可持续开启，每期自动识别首日，无需每月重开；重启保留。
自动模式按国服监控取得的会战编号匹配现有 Boss 数据源的开赛日程，并缓存已识别日期。
需开启会战监控；日程未取得时显示“待识别”，正常判定，不推测日期。台服请使用手动日期。
也可发送 `开启首日满补 YYYY-MM-DD` 改为手动指定日期；旧版已有日期设置保持手动，不自动切换模式。
游戏日以 UTC+8 每天 05:00 为边界。

开启后，仅该日的完整刀改计为补偿，确认击杀仍记尾刀，可直接识别的短时补偿保留补偿类型。
同时修正该日已入库的完整刀，已有尾刀与补偿保留；延迟读取的首日战报也按战斗结束日期处理。
第二天及其他日期自动恢复正常判定，设置重启后保留。自动模式下新一期会战自动更新首日。

`首日满补状态` 查看当前设置；`关闭首日满补` 关闭后续特殊判定，不回滚已修正记录。
网页仪表盘的监控状态栏（“第几天”旁）也提供同一个“首日满补”开关，
群主、群管或 bot 主人可操作，其他成员只读。开启或点旁边日期可选择“每期自动”或手动日期；
开关同时显示“生效中”“非首日”或“待识别”，与群指令共用设置和历史修正规则。
此模式是公会约定的统计规则，不能从 90 秒时长本身准确还原真实补偿身份。
升级后重启机器人，旧数据库会自动补充设置字段；无需更改伤害或分数。

### 群指令「状态」图片

「状态」复用本项目 WebUI 的 Boss 数据和头像资源，生成两列会战状态图，
包含排名、监控状态、今日已记录刀数、Boss 血量及预约 / 申请 / 挂树名单。
暂停监控时显示最后已知进度。近期入场人数仍来自游戏接口，不代表全部未结算成员。

在机器人使用的 Python 环境安装截图依赖：

```sh
pip install playwright
python -m playwright install chromium
# Linux 首次部署可用 python -m playwright install --with-deps chromium
```

重新构建并启动 `web/` 前端，将 `setting.py` 中 `WebSetting.status_image_url`
设为机器人能访问的截图页地址，默认 `http://127.0.0.1:5173/#/status-image`。
Windows 已安装 Edge 时也可将 `status_image_browser_channel` 设为 `"msedge"`。
截图页使用隔离浏览器内注入的本群数据，不需要网页登录账号、密码或开放群数据接口。
普通浏览器直接打开该网址不会显示群数据。浏览器未安装、前端未更新或页面无法访问时，
指令自动回退为原来的文字回复，详细原因记录在机器人日志中。

「今日出刀」「昨日出刀」共用上述截图环境，直接复用仪表盘的出刀分布表，
显示刀数、玩家标签和人数。仍按每日 05:00（UTC+8）换日，
完整刀计 1，尾刀 / 补偿计 0.5，每人最多计 3 刀。没有完整公会名单时明确标注统计范围，
截图失败时回退为原来的统计图片。两种截图只需配置同一项 `status_image_url`。
出刀统计截图采用 WebUI 夜间主题、较大字号和 2 倍像素密度，逻辑宽度仍为 512px；
仅在隔离截图浏览器中指定主题，不会改变成员正常浏览网页时的主题偏好。

## 🔧 账号绑定指南

> **提示**：以下说明中的"+" 表示空格

### 绑定方式

**一个 QQ 只绑一个游戏账号，绑一次所有群通用**（换公会、进新群都不用重新绑）。

**方式一：QQ 私聊机器人**

加机器人好友后，私聊发送：

```
【绑定账号 账号 密码】
【渠绑定账号 login_id token】
【台绑定账号 short_udid udid_viewer_id】
```

私聊发【绑定账号帮助】可以随时查看这份说明。

**方式二：网页端仪表盘**

登录网页端后，在「会战仪表盘」右上角点【绑定游戏账号】，填同样的信息即可。

两种方式写的是同一个号，用哪种都行。

## 🌐 WEBUI 配置说明

网页端（可选功能）首次部署需要修改两处配置，把默认地址换成你自己的：

### 1. `setting.py` → `WebSetting`

| 配置项 | 说明 |
| ------ | ---- |
| `api_host` / `api_port` | 后端 FastAPI 监听地址，默认 `0.0.0.0:12138` 一般无需修改 |
| `web_host` / `web_port` | **`web_host` 请改为你部署机器的内网 IP**（如 `192.168.1.100`），QQ 机器人回复的登录链接会使用该地址；仅本机访问可保持 `127.0.0.1` |
| `api_base` / `web_base` | 接口/页面路径前缀，一般无需修改 |

### 2. `web/.env` → 前端代理的后端地址

```dotenv
# 前后端在同一台机器：保持默认即可
VITE_API_URL=http://localhost:12138
# 机器人后端在另一台机器时，改为该机器的内网 IP，例如：
# VITE_API_URL=http://192.168.1.100:12138
VITE_API_BASE=/kanna_dependency
```

> 前端的启动方式、目录结构与全部接口说明见 [web/README.md](web/README.md)：`npm install` 后 `npm run dev`（开发模式）或 `npm run build`（生产构建）。
